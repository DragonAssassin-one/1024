# 1024

桌面级安全沙箱。Claude Code、Codex 和 DeepSeek Harness（dsh）在沙箱里工作，密钥留在沙箱外面。

安全放在第一位。好用放在第二位：你做的是选择和授权。沙箱里的 MCP 配置没有 API Key、密码或 Token 可以填。

## 它挡住什么

这三款 Agent 会读文件、改代码、执行命令，并通过 MCP 访问代码托管、数据库、搜索和其他服务。密钥若写在配置或环境变量里，跑在系统里的 Agent 自己就能读到。

1024 给每个 Agent 一个独立沙箱。

- 没点选的文件夹，打不开。
- 没打开的连接，连不上。
- API Key、密码和 Token 保存在沙箱外的系统钥匙串里。
- 沙箱里的 MCP 只有「已连接」和「未连接」。配置、环境变量和启动参数里都没有密钥。

Agent 调用已连接的服务时，凭证在沙箱边界附上；结果回到沙箱时，凭证已经去掉。Agent 被恶意内容带偏时，仍然读不到钥匙串，也进不了另一个沙箱。

## 使用

授权都在沙箱外面完成，一共三步。

1. **选 Agent。** Claude Code、Codex 或 dsh。每个 Agent 使用自己的沙箱。
2. **选文件夹。** 只勾选这次要交给它的项目。
3. **打开连接。** 常用 MCP 以开关列出。第一次授权使用系统登录或钥匙串，只做一次。换成另一个 Agent 时，不用再填密钥。

完成后，在沙箱里照常使用该 Agent。

沙箱内看到的是一份清单，没有密钥字段：

```text
Agent     Claude Code
文件夹    我的项目            已允许
连接
  GitHub  已连接
  数据库  未连接
  搜索    已连接
```

## 可以自己核对的承诺

- **密钥不进沙箱。** 在沙箱里打开连接设置、查看环境变量、翻看 MCP 配置，都找不到 API Key、密码或 Token。向 Agent 询问密钥，它也看不到。
- **默认拒绝。** 未允许的文件和网络地址不可用。
- **权限按沙箱分开。** Claude Code 的文件夹和连接只属于它自己的沙箱，Codex 和 dsh 同样各自独立。
- **凭证只在出沙箱时使用。** 沙箱内的进程拿不到凭证原文。
- **关闭即停。** 关掉某个连接后，之后的调用不再附带它的凭证。

## 连接怎么接

代码托管、数据库、网页搜索、邮件、即时通讯、日历和浏览器，都用同一套开关接入。沙箱内不填写敏感信息。

个别服务要求程序自己保存密钥。这类服务留在沙箱外运行，沙箱里只留一个不含密钥的入口。你在沙箱内仍然只看到开关。

## 请一起守住的边界

- 已允许文件夹里的文件，Agent 可以阅读。密钥放在沙箱外的钥匙串里。
- 对话会发给你所选 Agent 对应的模型服务。
- 已允许写入的文件，Agent 可以修改。沙箱划定它能碰到的范围；改动留不留，由你决定。

## 产品原则

1. **安全。** 密钥不进沙箱，文件和网络默认拒绝，权限按沙箱分开。做不到「沙箱内零密钥」的连接，留在沙箱外。
2. **好用。** 能用开关完成的，不用输入框。还要用户编辑配置文件、填写环境变量，或先理解 MCP，就不算做完。

## 现状

目前只有 **macOS 离线沙箱原型**，尚不是上面描述的完整产品。它允许用 Go CLI 启动一个受限命令，不能直接运行需要联网的 Claude Code、Codex 或 dsh 会话。

```sh
go build -o 1024 .
./1024 run --agent codex --folder /path/to/project -- /bin/sh
./1024 run --agent codex --folder /path/to/project --folder /path/to/other -- /bin/sh
./1024 run --agent codex --folder "$PWD" -- "$PWD/1024" status
./1024 run --agent codex --folder "$PWD" -- "$PWD/1024" mcp
```

需要 Go 1.25 或更新版本。`--agent` 目前只是本次运行的身份标签，不会自动安装或配置 Agent。可以重复使用 `--folder` 授权多个项目，第一个目录是命令的工作目录；每个目录先解析成真实路径、检查宿主状态保护，再加入沙箱权限，相同真实路径只授权一次。`status` 和 `sandbox_status` 会列出这些真实路径；在沙箱内访问经符号链接或 `/var` 别名传入的目录时，应使用状态中显示的路径。

每次运行会创建独立的临时 HOME，清空继承的环境变量，只允许读写指定目录和临时 HOME，允许读取启动所需的系统文件，默认拒绝其他文件和网络。唯一的例外是本次运行专属的 Unix socket：沙箱内的 `1024 status` 通过它向沙箱外进程读取 Agent、授权目录和已启用的连接名称。它不接收任意命令，不传输凭证，也不允许连接其他 Unix socket 或 TCP 地址。

`1024 mcp` 是遵循 MCP stdio 协议的入口，提供 `sandbox_status` 和下述按连接开关授权的 `github_identity` 只读工具。它必须在本次 `run` 创建的沙箱内启动；第三个命令可用于 MCP 客户端测试，但不代表三款 Agent 已自动配置。沙箱内的 MCP 配置只需指定这个可执行文件和 `mcp` 参数，不需要密钥字段。

### GitHub 连接原型

在**沙箱外的终端**执行：

```sh
./1024 credential github
./1024 connect github --agent codex
./1024 disconnect github --agent codex
```

第一条命令通过 macOS 钥匙串的交互提示录入令牌，不要在命令行参数、环境变量或项目文件中提供令牌。后两条命令分别打开、关闭 Codex 沙箱的 GitHub 开关；Claude Code 和 dsh 使用各自的 `--agent` 开关，共用宿主钥匙串条目。启用前会确认钥匙串中有凭证。沙箱内的 `sandbox_status` 只显示已启用的连接名称，`github_identity` MCP 工具仅在本 Agent 的 GitHub 开关打开时，向固定的 GitHub `/user` 接口请求身份并返回 `login` 和数值 `id`。每次调用重新检查开关；关闭后新的调用不再读取凭证。网络请求在宿主侧进行，沙箱的 TCP 网络仍被拒绝。

此功能**仅支持 GitHub 身份查询**，不提供仓库读写、通用 HTTP、任意 MCP 工具代理或浏览器访问。钥匙串中的凭证可被沙箱外的同一用户进程访问；本原型不抵御该用户权限下的其他恶意进程。连接开关保存在宿主用户的 `~/Library/Application Support/1024`，授权项目若覆盖该目录或系统钥匙串目录会被拒绝。

启动命令前会实际探测目录、文件、专属与非专属 socket、回环网络权限，验证失败时拒绝启动。命令退出后临时 HOME 和 socket 会被删除，项目目录中的改动保留；命令的非零退出码会原样返回。

本原型依赖 macOS 的 `sandbox-exec`。第三方程序若需要其他系统路径或服务，可能无法启动；请勿为使其启动而直接放开整个用户目录或网络。专属 socket 也不用于抵御沙箱外同一用户权限的其他进程。**除上述固定的 GitHub 身份查询外，其他连接、通用 MCP 凭证代理、在线 Agent 接入以及桌面授权界面均未实现。** 因此现在不能宣称做到完整的桌面沙箱产品承诺，也不要将它作为生产级安全边界。

在 macOS 上执行 `go test ./...` 可运行策略和端到端隔离测试；测试需要能绑定本机回环端口的执行环境。
