# 安全边界

## 保护目标

- Agent 进程不继承宿主环境变量；唯一的诊断例外是指向已授权可写目录的 `GOCOVERDIR`。它不通过命令行或 MCP 配置接收 GitHub 令牌。
- 未授权目录和网络默认不可用；每次运行只授权明确列出的可写、只读目录及专属 broker socket。
- 宿主侧 GitHub 开关按 Agent 分开，每次身份查询重新读取授权状态。损坏的授权状态会导致拒绝。
- HTTP 目标固定为 GitHub `/user`，不跟随重定向，不使用环境代理，且只返回经过筛选的身份字段。
- 仓库文本读取同时要求 GitHub 连接开关和本 Agent 的仓库白名单授权；读取路径、编码及大小由宿主限制。
- Codex 模式只放行一个精确回环模型端口，宿主侧每次重新检查开关并附加 Key；受限进程仅持有本次运行的本地 session 能力。
- 本机控制台仅绑定 `127.0.0.1`，修改操作验证精确 Host、Origin 和随机 CSRF；不提供凭证录入接口。任务取消会终止沙箱进程组。

## 使用前提与剩余风险

- 本原型仅在 macOS 上依赖 `sandbox-exec`，没有独立的特权守护进程或经过审计的桌面应用封装。
- 授权目录中的所有文件，包括其中的密钥或硬链接，均应视为可被 Agent 读取；可写目录中的文件可被修改。不要授权整个主目录。
- 同一宿主用户权限的其他进程可能访问钥匙串条目或干扰专属 socket；本原型不隔离这些进程。
- 同一宿主用户的恶意进程也能访问本机控制台或其页面令牌，因此本机 CSRF 防护不是宿主进程隔离方案；不要将控制台转发到外网。
- 受限 Codex 可读取自己短期配置中的本地 session 能力并主动调用宿主模型代理；它不能由此读取上游 Key，但仍可能发送任意被允许的模型请求，产生费用。宿主同用户进程也不在此威胁模型内。
- 模型代理目前将流响应缓冲至结束并限制为 16 MiB；超时、过大流或某些 Codex/模型功能可能失败。明文 Key 回显会被拒绝，但这不能替代对恶意上游或编码泄漏的审计。
- 允许的系统路径与设备节点是为了启动进程；不同 macOS 版本、第三方程序或系统服务可能需要额外能力，不能仅凭本机测试声称普遍安全。
- 某些 macOS 命令的用户数据库查询或 shell 初始化会被外层 Seatbelt 拒绝；当前不为兼容而开放整套系统服务。
- 关闭 GitHub 开关阻止之后开始的调用，不保证取消已经发出的请求。
- 对话若由未来的在线 Agent 发起，仍会发给相应模型服务；当前原型并未接通该服务。

若探针失败，运行器拒绝启动目标命令。不要通过放开整个主目录、所有网络或任意 Unix socket 的方式修复兼容问题。测试覆盖与未验证场景见 [测试说明](testing.md)。
