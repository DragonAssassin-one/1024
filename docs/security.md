# 安全边界

## 保护目标

- Agent 进程不继承宿主环境变量，不通过命令行或 MCP 配置接收 GitHub 令牌。
- 未授权目录和网络默认不可用；每次运行只授权明确列出的可写、只读目录及专属 broker socket。
- 宿主侧 GitHub 开关按 Agent 分开，每次身份查询重新读取授权状态。损坏的授权状态会导致拒绝。
- HTTP 目标固定为 GitHub `/user`，不跟随重定向，不使用环境代理，且只返回经过筛选的身份字段。

## 使用前提与剩余风险

- 本原型仅在 macOS 上依赖 `sandbox-exec`，没有独立的特权守护进程或经过审计的桌面应用封装。
- 授权目录中的所有文件，包括其中的密钥或硬链接，均应视为可被 Agent 读取；可写目录中的文件可被修改。不要授权整个主目录。
- 同一宿主用户权限的其他进程可能访问钥匙串条目或干扰专属 socket；本原型不隔离这些进程。
- 允许的系统路径与设备节点是为了启动进程；不同 macOS 版本、第三方程序或系统服务可能需要额外能力，不能仅凭本机测试声称普遍安全。
- 关闭 GitHub 开关阻止之后开始的调用，不保证取消已经发出的请求。
- 对话若由未来的在线 Agent 发起，仍会发给相应模型服务；当前原型并未接通该服务。

若探针失败，运行器拒绝启动目标命令。不要通过放开整个主目录、所有网络或任意 Unix socket 的方式修复兼容问题。测试覆盖与未验证场景见 [测试说明](testing.md)。
